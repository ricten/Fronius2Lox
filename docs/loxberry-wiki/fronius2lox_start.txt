===== 1. Überblick =====

**Fronius2Lox** fragt die **Fronius Solar API** (JSON über HTTP) direkt am Wechselrichter bzw. Datamanager ab, nie über Cloud oder Solar.web, und stellt die Werte als **MQTT-Topics** auf dem MQTT-Broker des LoxBerry bereit. Das LoxBerry-MQTT-Gateway macht daraus **virtuelle Eingänge** für den Loxone Miniserver. Das Plugin schreibt nichts in den Wechselrichter.

  Wechselrichter (Solar API)  ->  Fronius2Lox (LoxBerry)  ->  MQTT-Broker  ->  MQTT-Gateway  ->  Miniserver (virtuelle Eingänge)

Eigenschaften:

  * Bis zu **4 Wechselrichter bzw. Datamanager**, jeder unter eigenem Namen (''fronius/wr1/…'')
  * **Energiefluss:** PV-Leistung, Hausverbrauch, Netz (Bezug/Einspeisung), Batterie (Laden/Entladen, Ladestand), Erträge heute/Jahr/gesamt, Autarkie, Eigenverbrauch
  * **Wechselrichter-Details:** Spannungen, Ströme, Frequenz, Status mit Klartext, Fehlercode, Phasenwerte, Extremwerte
  * **MPP-Tracker:** DC-Leistung je Tracker; String 1 und 2 aus dem Archiv des Datenloggers, optional in Echtzeit per **Modbus TCP**
  * **Smart Meter**, **Batteriespeicher**, OhmPilot, Sensorkarte, String Control, Datenlogger, Fehler- und Ereignisprotokoll, wenn vorhanden (das Plugin fragt die Geräte beim Wechselrichter selbst ab)
  * **Nachtbetrieb:** Schaltet der Wechselrichter nachts ab (Symo/Primo mit Datamanager), ist das kein Fehler: ''schlaeft'' = 1, ''pv_w'' = 0, ''status/ok'' bleibt 1
  * MQTT-Broker des LoxBerry **oder eigener Broker**
  * Lebenszeichen (''fronius/status/ok'', ''zaehler'', ''ts''), Autostart, Watchdog, Healthcheck

===== 2. Installation =====

  - ZIP von der Release-Seite herunterladen.
  - **Gen24:** im Wechselrichter die Solar API freischalten (//Kommunikation → Solar API//).
  - LoxBerry → **Plugin-Verwaltung** → **Plugin installieren**. Die Installation startet den Dienst.
  - Plugin **Fronius2Lox** öffnen, IP des Wechselrichters eintragen, **Aktiv** anhaken, speichern.
  - Reiter **Test** → **Sofort abrufen** und **Selbstprüfung**. Nach spätestens einem Abfrageintervall (10 s) erscheinen Werte unter ''fronius/<name>/*''.

==== 2.1 Update ====

Als Update installieren. Konfiguration und Daten bleiben erhalten; neue Einstellungen ergänzt das Plugin automatisch mit Standardwerten.

**Automatische Updates:** Ab Version 0.5.0 liefert Fronius2Lox eine ''release.cfg'' im GitHub-Repository mit. Neue Installationen stehen in der Plugin-Verwaltung bei „Automatische Updates“ auf //Releases//: LoxBerry prüft täglich und installiert neuere Versionen selbst. Bei einer bereits installierten Version einmal von Hand auf 0.5.0 (oder neuer) aktualisieren, danach lässt sich die Einstellung (//Aus//, //Benachrichtigen//, //Releases//) in der Plugin-Verwaltung ändern.

**Immer das neueste Release:** [[https://github.com/ricten/Fronius2Lox/releases/latest/download/fronius2lox.zip|fronius2lox.zip]] (ZIP ohne Version im Dateinamen, zeigt immer auf die aktuelle Version).

==== 2.2 Deinstallation ====

Plugin entfernen. Dienst und RAM-Daten werden gelöscht.

===== 3. Konfiguration (LoxBerry) =====

Reiter: **Einstellungen · MQTT · Einbindung in Loxone · Test · Logdateien**. Änderungen wirken ohne Neustart; jeder Reiter speichert nur seine eigenen Einstellungen.

==== 3.1 Allgemein ====

^ Einstellung ^ Standard ^ Beschreibung ^
| Abfrageintervall | 10 s | 5–300 s (Fronius verlangt mindestens 4 s zwischen zwei Abfragen) |
| Details je Wechselrichter | an | Spannungen, Ströme, Frequenz, Status, Phasenwerte, Extremwerte |
| Smart Meter, Batteriespeicher, Weitere Geräte | an | Nur abgefragt, wenn der Wechselrichter sie meldet |
| Datenlogger | an | Version, Zeitzone, LEDs (nicht GEN24) |
| Archiv (Fehler, Ereignisse, Strings) | an | Letzter Fehler und Ereignisse des Tages, String 1 und 2 (nicht GEN24), alle 5 min; die String-Werte sind Werte im Aufzeichnungsintervall (5–30 min), keine Echtzeitwerte |
| Rohwerte | aus | Alle Felder der Antworten zusätzlich unter ''fronius/<name>/raw/…'' |

==== 3.2 Nachtbetrieb ====

^ Einstellung ^ Standard ^ Beschreibung ^
| Nachtbetrieb | an | Aus: Jede Nichterreichbarkeit ist ein Fehler |
| Geringe Leistung bis | 100 W | War die PV-Leistung beim letzten Abruf höchstens so hoch (abends), gilt der Ausfall als Nacht |
| Breitengrad / Längengrad | leer | Optional; nur nötig, damit der Ausfall auch nach einem Neustart mitten in der Nacht als normal erkannt wird |

Im Nachtbetrieb gilt ''schlaeft'' = 1, ''verbunden'' = 0, ''pv_w'' = 0, ''status/ok'' bleibt 1. Fällt der Wechselrichter bei hoher Leistung aus (tagsüber), ist das ein Fehler: ''status/ok'' = 0.

==== 3.3 Wechselrichter ====

Bis zu vier Einträge. Ein Kästchen zeigt, ob die Solar API erreichbar ist (grün/rot/grau).

^ Spalte ^ Beschreibung ^
| Aktiv | Nur aktive Einträge werden abgefragt |
| Name im Topic | ''a-z 0-9 _ -'', leer = ''wr1'', ''wr2'' … |
| Host/IP, Port | Adresse des Wechselrichters bzw. Datamanagers (Port 80, HTTP) |

Hängen mehrere Wechselrichter an **einem** Datamanager (Solar Net), genügt dessen Adresse: Alle Geräte erscheinen unter ''wr/<Nr>/…''. Bei Gen24 hat jeder Wechselrichter seine eigene Adresse.

==== 3.4 MPP-Tracker per Modbus TCP (optional) ====

Die Solar API liefert Spannung und Strom von Tracker 2 bis 4 nur beim GEN24/Tauro/Verto. Beim Symo kommen String 1 und 2 aus dem Archiv. Für **Echtzeitwerte** zusätzlich Modbus TCP nutzen (nur lesend, SunSpec-Modell 160):

  - Im Datamanager unter //Einstellungen → Modbus// Datenausgabe über Modbus **tcp**, SunSpec-Modelltyp **int + SF**, Port 502 einstellen.
  - Im Plugin „MPP-Tracker per Modbus TCP lesen“ anhaken und speichern.

Dann gelten ''spannung_dc_v'', ''strom_dc_a'', ''leistung_dc_w'' (Tracker 1) und ''…_dc_2_…'' (Tracker 2) mit den gemessenen Werten. ''wr/<Nr>/modbus_ok'' zeigt den Zustand.

==== 3.5 MQTT-Broker (Reiter MQTT) ====

Oben zeigt ein farbiges Feld das **Gateway-Abo** (grün ab einem passenden Abo, rot nur ohne Abo).

^ Einstellung ^ Standard ^ Beschreibung ^
| Eigenen MQTT-Broker verwenden | aus | Aus: Broker des LoxBerry (Zugangsdaten verwaltet LoxBerry) |
| Host/IP, Port | - / 1883 | Eigener Broker (ohne TLS) |
| Benutzer, Passwort | leer | Optional; das Passwort wird nie angezeigt oder geloggt |

Mit eigenem Broker erreichen die Werte den Miniserver nur, wenn das MQTT-Gateway diesen Broker abonniert.

==== 3.6 Test und Logdateien ====

^ Aktion ^ Wirkung ^
| Sofort abrufen | Zeigt alle Topics und Werte, die das Plugin gerade veröffentlichen würde |
| Selbstprüfung | Konfiguration, Solar API, Energiefluss, Broker, Gateway-Abo, Dienst |
| Dienst neu starten | Beendet und startet den Dienst |

Der Loglevel wird in der LoxBerry-Plugin-Verwaltung eingestellt.

===== 4. MQTT-Topics (Referenz) =====

Schema ''fronius/<name>/<wert>'', Zahlen mit Punkt ohne Einheit, Zustände 0/1, nicht retained. Welche Felder ein Gerät liefert, hängt von Modell und Firmware ab. Die vollständige Liste steht im [[https://github.com/ricten/Fronius2Lox/blob/main/docs/wiki/MQTT-Topics.md|Repository]] und im Plugin im Reiter //Einbindung in Loxone//.

^ Topic ^ Bedeutung ^
| ''pv_w'' | PV-Leistung (W), nachts 0 |
| ''haus_w'' | Hausverbrauch (W), nur mit Smart Meter |
| ''netz_w'' | Netz (W): + Bezug / − Einspeisung |
| ''netz_bezug_w'', ''netz_einspeisung_w'' | Bezug / Einspeisung (W, je ≥ 0) |
| ''batterie_w'' | Batterie (W): + Laden / − Entladen (wie bei Senec2Lox) |
| ''batterie_soc'' | Ladestand (%) |
| ''energie_tag_wh'', ''energie_jahr_wh'', ''energie_gesamt_wh'' | Erträge (Wh); GEN24: Tag und Jahr immer leer |
| ''autarkie'', ''eigenverbrauch'' | % (nur mit Smart Meter) |
| ''wr/<Nr>/leistung_ac_w'', ''spannung_ac_v'', ''strom_ac_a'', ''frequenz_hz'' | Wechselrichter AC |
| ''wr/<Nr>/spannung_dc_v'', ''strom_dc_a'', ''leistung_dc_w'' (und ''_dc_2_'') | MPP-Tracker (Leistung berechnet oder per Modbus gemessen) |
| ''wr/<Nr>/string_1_spannung_v'', ''…_strom_a'', ''…_leistung_w'' (ebenso ''string_2_'') | String 1 und 2 aus dem Archiv (nicht GEN24) |
| ''wr/<Nr>/status_code'', ''status_text'', ''fehler_code'' | Status (7 = Betrieb), Klartext, Fehlercode (0 = kein Fehler) |
| ''zaehler/<Nr>/leistung_w'' u. a. | Smart Meter (Vorzeichen nach Einbauort) |
| ''speicher/<Nr>/soc'' u. a. | Batteriespeicher |
| ''verbunden'', ''schlaeft'' | Wechselrichter erreichbar / abgeschaltet (Nacht) |
| ''fronius/status/ok'' | Alle Geräte liefern Werte oder schlafen nachts (1/0); der Broker setzt 0, wenn der Dienst abbricht |
| ''fronius/status/zaehler'' | Lebenszeichen 0–999 |
| ''fronius/status/ts'' | Zeitstempel des letzten Durchgangs |

===== 5. Miniserver Anbindung =====

==== 5.1 MQTT-Gateway ====

Das Abonnement ''fronius/#'' trägt das Plugin nur beim **Gateway V1** selbst ein. Das **Gateway V2** liest die Abo-Datei von Plugins nicht: Dort ''fronius/#'' **von Hand** im MQTT Gateway unter Abonnements eintragen (das Plugin prüft es im Reiter MQTT). ''fronius/status/ok'' und ''fronius/status/zaehler'' im Gateway auf **No Cache** stellen.

==== 5.2 Virtuelle Eingänge ====

Das Gateway ersetzt ''/'' durch ''_'': ''fronius/wr1/pv_w'' wird zu ''fronius_wr1_pv_w''. Die Tabelle aller Eingänge zeigt das Plugin im Reiter //Einbindung in Loxone//.

^ Eingang ^ Bedeutung ^
| ''fronius_wr1_pv_w'' | PV-Leistung (W) |
| ''fronius_wr1_haus_w'' | Hausverbrauch (W) |
| ''fronius_wr1_netz_w'' | Netz (W): + Bezug / − Einspeisung |
| ''fronius_wr1_batterie_soc'' | Ladestand (%) |
| ''fronius_wr1_energie_tag_wh'' | Erzeugung heute (Wh) |
| ''fronius_wr1_verbunden'' | 1 = Wechselrichter erreichbar |
| ''fronius_status_ok'' | 1 = alle Geräte liefern Werte |
| ''fronius_status_zaehler'' | Lebenszeichen für die Ausfallerkennung |

Für einen Alarm in Loxone besser ''fronius_status_ok'' = 0 auswerten (echter Fehler, auch tagsüber) als ''verbunden'', das nachts 0 ist. Dieses Plugin hat keine Befehle (die Solar API ist nur lesend).

===== 6. Tipps & Tricks =====

  * ''batterie_w'' und ''netz_w'' haben dieselben Vorzeichen wie bei Senec2Lox (Bezug und Laden positiv): Pläne lassen sich zwischen Senec und Fronius tauschen.
  * Das Plugin Lox2PVOutput liest die Fronius-Werte und lädt sie zu pvoutput.org hoch.
  * Ein GEN24 liefert keinen Tageswert: die Tagesenergie in Loxone oder mit Lox2PVOutput aus der Leistung bilden.
  * ''fronius_status_zaehler'' im Miniserver überwachen: bleibt er stehen, läuft der Dienst nicht mehr.

===== 7. FAQ / Troubleshooting =====

^ Symptom ^ Ursache / Lösung ^
| Kästchen grau, „abgeschaltet (Nacht) – kein Fehler“ | Nachts normal. Morgens dauert es, bis Wechselrichter und Datamanager antworten |
| Kästchen rot, „nicht erreichbar“ | IP/Host falsch, Wechselrichter aus, Firewall. Im Browser ''http://<IP>/solar_api/GetAPIVersion.cgi'' aufrufen |
| „Solar API nicht gefunden (HTTP 404)“ | Gen24: Solar API im Wechselrichter freischalten |
| Keine Werte in Loxone, aber in MQTT | Gateway V2: Abo ''fronius/#'' von Hand eintragen; der Reiter MQTT zeigt, ob es steht |
| ''haus_w'', ''netz_w'' fehlen | Ohne Smart Meter kennt der Wechselrichter weder Haus- noch Netzleistung |
| Keine ''string_1_…''/''string_2_…'' | Nur Symo/Primo/Hybrid (nicht GEN24), Option „Archiv“ an; Werte kommen im Aufzeichnungsintervall. Echtzeit: Modbus TCP |
| ''modbus_ok'' = 0 | Modbus TCP im Datamanager einschalten (tcp, int + SF, Port 502); der Grund steht im Log |
| ''status/ok'' = 0 | Mindestens ein Gerät antwortet nicht. Name und Grund stehen im Reiter MQTT und im Log |

Weitere Hinweise: [[https://github.com/ricten/Fronius2Lox/blob/main/docs/wiki/Fehlersuche.md|Fehlersuche im Repository]].
